# 집 전체 걷기 영상 · 영상+사진 함께 입력 (2026-11-26)

목표: 집 안을 폰으로 찍으며 걷기만 하면 3D·공간·문·용도가 나온다. 영상만, 사진만, **영상+보충 사진** 세 가지 입력을 모두 받는다.

## 시험 자료 (`tools/make-walkthrough.py`)

- LH 평면도(기본 227번, 실제 SfM 시험 단지)의 구조를 자체 렌더한 **걷기 영상**이다(960×640, 3fps, 486프레임, 162초).
- 큰 공간에서 출발해 문을 지나 각 방에 들어간다. 방 안에서는 작은 원을 돌며 벽을 보고, 되돌아 나와 다음 방으로 간다. 경로는 벽에서 0.25m 이상 떨어진 A* 경로다.
- 정답(방·문·프레임별 카메라)은 `artifacts/walkthrough/<집>/property.gt.json`에 있으며 추론에 쓰지 않는다. 생성에 약 8분 걸린다.
- 가구가 없는 합성 영상이며 실제 폰 영상(흔들림·노출·흰 벽)은 아니다.

## 드러난 문제와 수정

1. **흰 벽 프레임 탈락** (`frames.py`)
   - 원인: 선명도 기준이 영상 전체 중앙값의 35%라서, 벽을 가까이 본 무늬 적은 프레임 113/486장이 빠졌다. 그 빈틈이 궤적을 끊었다.
   - 수정: 앞뒤 ±1.5초 중앙값 기준으로 바꿨다. 흔들림만 빼고 흰 벽은 남긴다.
2. **궤적 이상치 연쇄 제거** (`sfm.py trajectory_deviation`)
   - 원인: 기존 판정은 이웃 중간점과의 거리였다. 프레임 간격이 고르지 않으면 정상 프레임도 벗어난 것으로 보였다. 끝 프레임은 "이웃까지 거리의 절반"으로 판정해서, 시작 부분 46장이 한 장씩 연쇄로 지워졌다.
   - 수정: 이웃을 잇는 선분까지의 거리로 판정한다. 양 끝은 다음 두 프레임을 잇는 직선까지의 거리를 쓴다. 등록 수는 314/373 → **465/469**가 됐다.
3. **긴 영상 매칭** (`sfm.py hybrid_pairs`)
   - 원인: 150장이 넘으면 연속 매칭만 해서, 되돌아온 방이 이어지지 않았다.
   - 수정: 연속 15장 + 2^k 간격에 더해, 핵심 프레임 약 100장끼리 전체 쌍(루프 폐합)을 매칭한다. 400장 기준 약 12,000쌍이다.
4. **문 근거 0** (`property_graph.py`)
   - 원인: 양쪽 카메라가 모두 문을 화각에 담아야 근거로 셌다. 걸으며 찍으면 문을 앞으로만 지나가고 뒤돌아보지 않는다.
   - 수정: 문을 화각에 담은 카메라의 시선이 문을 지나면 충분하고, 반대쪽은 같은 3D 점을 본 것만 요구한다.
   - 사진 경로 실제 SfM 시험(26채): IoU 0.824→**0.833**, 문 재현율 0.801→**0.847**, 정밀도 0.887→0.869. 검증 6채는 변화 없음.

## 영상 + 사진 함께 입력

- CLI: `python -m spacecapture process 집.mp4 --photos 보충사진폴더 --max-frames 400`
- 웹: 자료 종류 "영상 + 보충 사진"에서 영상 1개와 사진 3~150장을 고른다. 서버는 영상 작업에 `--max-frames 400`을 준다.
- 영상 프레임은 한 카메라(같은 초점·왜곡)로, 사진은 사진마다 카메라로 특징을 뽑는다. 사진은 사진끼리 전체 쌍과 핵심 프레임 전부와 매칭한다. 초점 사전값은 각 이미지 긴 변 대비 비율로 준다.
- 영상 궤적 이상치 제거는 영상 프레임에만, 사진 포즈 검사(관측점 12개 미만·초점 이상)와 정렬 후 검사(촬영 높이·배율·고립 묶음)는 혼합 입력에도 적용한다.
- `scene.source.kind="video+photos"`. 카메라에는 `video_frame` 또는 `source_photo`가 붙는다.

## 결과 (LH 227번 구조, 정답과 비교)

| 입력 | 등록 | 카메라 정렬 오차 | 공간 | IoU | 시간 |
|---|---:|---:|---:|---:|---:|
| 걷기 영상만 (수정 전) | 314/373 | 0.52cm | 6/5, 대응 5 | 0.632 | 9.5분 |
| 걷기 영상만 (수정 후) | 465/469 | 0.39cm | 6/5, 대응 5 | 0.676 | 10.9분 |
| **영상 앞부분(방 3개) + 사진 42장(나머지 방 2개)** | **319/323(사진 42/42)** | **0.16cm** | 6/5, 대응 5 | **0.733** | 6.8분 |

- 혼합 입력에서는 영상에 없던 두 방이 사진으로 같은 좌표계에 들어왔다. 두 방의 용도 추정(침실·침실)도 평면도 글자와 맞았다.
- Brush 640px·3,000스텝 학습에 74.5초 걸렸고, 영상 카메라 1개와 사진별 카메라를 섞어도 문제없었다. 뷰어(Playwright Chromium)에서 3D·용도 라벨·업로드 선택지를 확인했고, JS 오류는 favicon 404뿐이었다.
- 남은 차이: 복도가 거실과 0.8m 폭으로 이어져 따로 공간이 된다. 정답 변환은 거실에 포함시킨다. 그래서 문 재현율이 0.5다.
- 회귀: `synth-walkfix-regression` +2.7/+2.0cm(60/60). 기존보다 1장 더 쓰여 궤적 RMSE는 0.16→1.02cm다. Python 103개 통과, `npm run build` 통과.

## 실제 같은 재질로 다시 시험 (2026-11-26 오후)

- 사용자 의견: "무지개색 느낌이라 이상하다". 원인은 SfM 시험용 알록달록한 노이즈 재질(`unique_noise`)이었다.
- `texture_style="interior"`를 추가했다(`synth_property._texture_interior`). 구성은 엇갈린 나무 마루, 무늬 적은 미색 벽지, 걸레받이, 차분한 액자·콘센트, 흰 천장이다. 면마다 난수가 달라 반복 무늬는 없다. 면 사이 틈은 벽색으로 채운다. `tools/make-walkthrough.py`의 기본값이 `--style interior`가 됐다.
- 이 영상은 실제 흰 벽 문제에 가까운 시험이다.
  - 처음에는 477장 중 380장만 등록됐고, 침실 구간 47장이 통째로 촬영 높이 2~5.4m(실제 1.45m)의 다른 위치에 붙었다.
  - 관측점 0~3개 프레임도 등록됐다. 결과는 공간 4/5, IoU 0.483이었다.
- 수정: 사진 입력에만 쓰던 검사를 **영상에도** 적용한다.
  - 관측점 12개 미만 포즈 제외(`sfm.run_sfm`).
  - 정렬 후 촬영 높이 0.6m·국소 높이 비율·고립 묶음 검사(`pipeline.process`).
- 결과:

| 영상 | 등록·사용 | 공간 | IoU | 문 재현율 |
|---|---|---|---:|---:|
| 실제 같은 재질 (수정 전) | 380/477 | 4/5 | 0.483 | 0.75 |
| 실제 같은 재질 (수정 후) | 378 등록 → 검사 후 328 | **5/5** | **0.687** | **1.0** |
| 기존 노이즈 재질 (수정 후) | 464/469 | 6/5 | 0.710 | 0.5 |

- 회귀: synth 방 영상 +2.9/+1.9cm, 궤적 RMSE 0.17cm(58대). Python 104개. Brush 960px·5,000스텝 3.0분. 위에서 본 화면을 README 대표 그림으로 바꿨다.
- 남은 과제: 무늬 없는 벽만 보이는 프레임 약 20%가 빠진다. 촬영 안내(벽에 너무 붙지 않기, 문틀·바닥선이 보이게)와 함께 실제 폰 영상으로 확인해야 한다.

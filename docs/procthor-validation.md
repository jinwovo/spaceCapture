# 외부 합성 집 구조로 사진 복원 검사

이 문서는 천장 신경망을 추가하기 전의 처리 기록이다. 이후 변경과 현재 천장 상태는 [천장 학습·적용 기록](ceiling-learning.md)을 참고한다. 적용 전 수치는 `current-before-ceiling-model.json`에도 보관했다.

2026-11-09. 네트워크 복구 뒤 [공식 ProcTHOR-10K 저장소](https://github.com/allenai/procthor-10k)의 검증 분할을 내려받았다. Apache-2.0 LICENSE를 원본과 함께 보관했다. 버전 `439193522244720b86d8c81cde2e51e3a4d150cf`를 고정했고 Git LFS 기록과 받은 파일의 SHA-256이 일치한다.

다운로드는 **1,000개 집 구조 / 5,094,681바이트 / 3.576초**다. 신경망·시뮬레이터·외부 가구 및 재질 에셋을 설치하지 않았다. 원본은 `samples/external/procthor-10k/`, 검사 결과는 `artifacts/procthor-validation/`에 있다.

이 집 구조 JSON으로 벽·바닥·천장·열린 문을 만들고 기존 NumPy 렌더러로 사진을 생성했다. 가구를 제외하고 창문·현관을 막았으며 벽 두께는 0이다. **실사 매물 사진이나 공식 ProcTHOR 시뮬레이터 렌더링은 아니다.** 방·문 정답은 추론기에 주지 않고 평가 때에만 사용했다. 카메라 정답으로 좌표·배율을 맞춘 비교이므로 실측 배율 정확도와 구분한다.

1,000개 중 현재 변환기로 처리 가능한 구조는 **492개**다. 빈 벽으로 이어진 개방형 의미 영역 **287개**, 내부 문의 완전 개방 상태 미확인 **221개**는 보류했다. 후자는 닫힌 문으로 판별했다는 뜻이 아니다. 원본 검증 분할은 평가 전용으로 표시했고 `training-pairs`에 넣으면 거절한다. 신경망 학습은 하지 않았다.

평가 점수를 보기 전에 선택 규칙을 고정했다. 공간 3개 또는 4개, 경계상자 100㎡ 미만이며 변환 가능한 첫 집을 골랐다. 선택 결과는 `val-0140`(ㄱ자 공간 포함)과 `val-0043`이다. 이후 이 두 사례로 구현을 개선했으므로 미사용 테스트 집의 일반화 점수로 주장하지 않는다.

발견한 문제와 변경:

- 고정 1.1m 폭으로만 분할하면 넓은 개구부 양쪽 공간이 합쳐졌다. 1.5/1.9/2.3m에서도 내부 영역을 검사하되, 이미 발견한 좁은 복도는 유지하고 새 분할에는 면적과 촬영 근거를 요구한다. 결과는 공간 후보다.
- 등록 사진에도 관측 3D 점이 0개이거나, 점군 범위에 비해 매우 멀고 지지점이 적은 포즈가 있었다. 사진 순서 대신 관측점 수와 점군 범위로 이런 포즈를 제외하고 재조정한다. 멀리 떨어져도 관측 근거가 충분한 사진은 제외하지 않는다. 모든 잘못된 포즈를 검출하는 방식은 아니다.
- 제외된 카메라의 초점거리를 대표값으로 쓰지 않도록 등록 카메라에서 대표값을 계산한다. 재조정은 좌표계 자유도를 고정하고 사용 가능한 해인지 검사한다.

첫 집은 사진 **76장 중 중복 1장 제외, 75/75장 등록**, SfM **48.4초**다. 영역 IoU **0.1448→0.5025**, 공간 후보 **1개→2개**(정답 3개), 문 연결 **1/2개**, 해당 문 중심 오차 **7.50cm**, 폭 오차 **2.50cm**다. 카메라 정답 정렬 RMSE는 **0.635cm**다. 넓은 문 하나와 완전한 영역 분리는 놓친다.

두 번째 집의 상세 수치는 `artifacts/procthor-validation/baseline.json`, `current.json`을 참고한다. 처음에는 104장을 모두 등록했어도 카메라 위치 이상치 때문에 도면 비교가 무너졌다. 재실행과 포즈 제외·분할 개선을 함께 수행했으므로 각 변경의 단독 효과를 측정한 결과는 아니다. 두 합성 집의 개발 검사만으로 집 전체 완성 도면 성능을 보장하지 않는다.

최종 재실행은 **104장 중 포즈 6장 제외, 98장 등록**, SfM **73.7초**였다. 공간 후보 **4/4**, IoU **0.8723**, 문 연결 **3/3**, 문 중심 평균 오차 **15.04cm**, 폭 평균 오차 **14.15cm**, 카메라 정답 정렬 RMSE **0.859cm**다. 관측 영역과 문 연결 후보의 기하 비교이며 방 용도나 실제 통행 가능 여부의 확정이 아니다. 높은 천장은 **3.2963m vs 4.2040m(−90.77cm)**로 잘못 잡았다.

첫 집의 Brush는 **640px / 3,000스텝 / 최대 15만 개**, **58.8초**, 프로세스 최대 작업 집합 **786MiB**, 종료 코드 0으로 완료됐다. 실제 PLY는 **34,172개** 스플랫이다. Chrome의 Radeon 780M 렌더러에서 3D/평면도 전환을 확인했고 JS 예외 **0개**다. 저해상도 학습 결과여서 흐리다. 증거: `artifacts/procthor-validation/browser/`.

천장은 해결하지 못했다. 첫 집은 정답 **4.2258m**를 **3.7477m**로 검출해 **−47.81cm** 낮게 추정했다. 높은 천장을 제외하는 `cam_top+2.5m` 조건과 집 내부 수직면의 높이층을 천장으로 오인할 위험이 드러났다. 기존 `synth`도 **2.4m 가정 / 정답 2.5m**다. 정답으로 높이를 덮어쓰지 않았다.

기존 자체 합성 두 집의 IoU **0.9239/0.9092**, 별도 대응점 평균 오차 **0.410/0.608cm**는 유지됐다. 기존 `synth` 가로·세로 **+2.8/+3.1cm**도 유지됐다. 최종 코드로 영상 전체를 다시 처리한 `synth-download-regression`은 **59/59장**, 가로·세로 **+2.7/+2.3cm**, 궤적 RMSE **0.16cm**로 3.5cm 기준을 통과했다. `video-regression.json`에 보관했다. 외부 실제 사진·도면 평가 **0건**, 신경망 학습 **미수행**이다.

추가 브라우저 검증에서 두 번째 집의 영역 후보 **4개**, 사진 근거 연결 **3개**, 문 양쪽 썸네일 **12장** 로드 및 양쪽 촬영 위치 이동을 확인했다. JS 예외 **0개**. `artifacts/procthor-validation/property-browser/` 참고. 로컬 앱은 `http://127.0.0.1:8765`에서 실행 중이다.

재실행:

```powershell
.\.venv\Scripts\python.exe -X utf8 tools/fetch-procthor.py
.\.venv\Scripts\python.exe -X utf8 tools/prepare-procthor.py
.\.venv\Scripts\python.exe -m spacecapture photos artifacts/procthor-validation/val-0140/photos --name procthor-val-0140 --no-splat
.\.venv\Scripts\python.exe -m spacecapture photos artifacts/procthor-validation/val-0043/photos --name procthor-val-0043 --no-splat
.\.venv\Scripts\python.exe -X utf8 tools/validate-procthor.py
```

`baseline.json`은 변경 전 기록이므로 다시 덮어쓰지 말 것. 최종 코드의 전체 검사 **46개 / 8.03초**, compileall, 뷰어 빌드는 통과했다(기존 큰 번들 경고만 있음).

# LH 실제 평면도 기반 검증 (2026-11-10)

공공데이터포털 [LH 주택 평면도 현황(15037046)](https://www.data.go.kr/data/15037046/fileData.do)의 실제 국내 공공주택 평면도로 정답 구조를 만들고, 그 구조를 자체 렌더링한 사진을 기존 사진→SfM→공간·문 후보 파이프라인에 넣어 비교했다. **사진은 합성**이다. 실제 매물 사진의 정확도가 아니며 `real_property_validation=false`로 기록한다.

## 자료

- 공식 다운로드 흐름(`check-limit` → `fileDownload`)으로 받음. 보안 문자 요구 없음. ZIP **356,725,466바이트 / 43.8초**, SHA-256 `57809e0f961ab486…`.
- 평면도 **281장 / 65개 단지**와 주택형·전용/공급면적 표 281행. `.json` 확장자지만 일부는 `<img src='data:image/...'>` 조각이다. 이용허락범위 "제한 없음", 저작권 확보 표시 N. 상업 학습 전에 제공기관 확인이 필요하다.
- 준비: `tools/prepare-lh-floorplans.py` → `samples/external/lh-floorplans/{manifest,table}.json, images/`.

## 평면도 → 정답 구조 (`spacecapture/plan_image.py`)

1. 축척: 사람(이번에는 Claude 시각 판독)이 도면의 치수 사슬 합계를 주석 파일(`annotations/plan-XXXX.json`)에 적고, 이미지의 끝 눈금선 위치는 자동 검출한다. 문자 인식은 없다. 치수는 벽 중심선 기준으로 가정했다.
2. 벽: 회색값 40 미만 + 6cm 열림. 외곽은 3.2m 닫힘으로 창을 메운 뒤 채운다. 외벽 띠 두께는 도면에서 측정한다(9번 0.31m, 227번 0.36m).
3. 문: 가로·세로 1.05m 닫힘으로 생긴 틈 중 두 실에 닿고 폭 0.55~1.1m인 것. 7cm보다 얇은 닫힘 띠는 벽 끝이 어긋난 열린 통로이므로 실을 나누지도, 문으로 세지도 않는다.
4. 실: 남은 바닥을 연결 요소로 나눠 5cm 격자 다각형으로 만든다. 2.5㎡ 미만(실외기실·팬트리 등)은 렌더링하지만 사진·정답 평가 대상에서 뺀다.
5. 렌더 설정: 실 다각형의 각 변을 벽면으로, 문 틈에는 측면·인방(2.1m)을 만들어 **벽 두께를 유지**한다. 천장 2.3m 가정. 실마다 12장, 문마다 앞뒤 ±1.4m·문틀 안을 지나는 동선 사진(총 9장).

사람 확인을 대신해 원본과 변환 결과 겹침 이미지(`artifacts/lh-validation/plan-XXXX/overlay.jpg`)를 보고 확인했다. 정답은 추론에 전달하지 않는다.

## 이 검증에서 드러나 고친 문제

| 문제 | 원인 | 조치 |
|---|---|---|
| SfM이 방마다 다른 배율로 무너짐(카메라 오차 수백 m) | 자체 텍스처가 모든 면에 같은 사각형 모서리·글꼴 숫자를 반복 → 같은 면을 전혀 보지 않는 사진 쌍이 30~46개 대응점으로 기하 검증 통과(상위 25쌍 모두 공유 면 0) | 면마다 고유한 다중 스케일 노이즈 텍스처(`texture_style=unique_noise`). 기존 자료는 기존 텍스처 유지. 129/132장 등록, 카메라 RMSE 0.5cm |
| 작은 방(욕실·다용도실) 미검출 | 1.1m 침식 후 0.6㎡ 미만 중심 영역 제거 | 0.75m 침식에서 기존 중심과 떨어져 있고 안에 카메라 2대 이상인 영역 추가. 기존 영역에 붙은 나머지를 쓰는 방식은 0043 IoU를 0.89→0.54로 떨어뜨려 폐기 |
| 잘못된 포즈 3장 잔존(227번) | 포즈 제외 후 점 삭제로 다른 사진의 관측 수가 줄어 새로 기준에 걸리는데 필터를 한 번만 실행 | 변화가 없을 때까지 최대 4회 반복. 같은 복원에서 375→0.35cm |
| 욕실 9장 묶음이 통째로 잘못된 위치·배율(6번 중 5번) | 0.709m 문으로만 약하게 이어져 전역 SfM이 묶음의 위치·배율을 잘못 정함. 높이·관측 수·초점은 정상 | 정렬 후 세 가지 검사로 제외 후 재조정·재정렬: 촬영 높이 0.6m 이상 차이, **본 점 기준 국소 촬영 높이 비율 1.6배 초과(배율 무관)**, 3m 넘게 떨어진 작은 묶음 중 공유 점이 10% 미만. 22개 사진 장면에서 잘못된 묶음만 잡고 올바른 카메라는 0장 |
| 벽 경계 탐색 `IndexError` | 히스토그램 피크가 없거나 모두 약할 때 빈 배열 인덱싱 | 해당 방향 경계 없음으로 처리(기존 대체 경로 사용) |
| 정답 변환 오류(227번 집이 두 쪽으로 막힘) | 1.03m 열린 통로를 문 닫힘이 얇은 띠로 막음 | 7cm 미만 닫힘 띠 무시. 9번 정답과 사진은 이전 변환기로 함께 만들어 서로 일관 |

- 9번은 개발용이다. 텍스처·작은 방 보완·포즈 검사를 이 집으로 조정했다. 227번은 조정 뒤 처음 실행한 평면도다. 이후 227번에서 정답 변환 오류와 포즈 필터 반복 문제를 찾아 고쳤으므로 완전한 미사용 시험은 아니다.
- 마커가 없는 촬영 높이 가정으로도 카메라 간 거리 비율 **1.0028**, 정렬 배율 1.003. 합성 사진이 모두 1.45m에서 찍혀 가정과 일치하기 때문이며 실제 촬영의 축척 정확도가 아니다.
- 천장은 모두 2.4m 가정(정답 2.3m). 천장 후보가 생기지 않았다.

### 남은 한계

- 문 폭이 0.75m보다 넓은 작은 방(욕실 0.81~0.86m)은 실행에 따라 별도 공간으로 잡히지 않는다(227번 g1의 4/5, 9번 공용욕실).
- 알고리즘은 침실 쪽 복도를 별도 공간으로 나누지만 정답은 거실·주방·복도를 한 공간으로 정의한다. 복도 영역이 다른 방에 잘못 대응되는 경우가 있어 IoU와 문 정밀도가 깎인다.
- 9번 공용욕실 묶음은 6번 중 5번 잘못 배치됐다. 이제 자동 제외(공간·문 누락)로 처리하지만 올바른 배치를 복원하지는 못한다. 좁은 문으로만 이어진 작은 방은 문 앞뒤 촬영을 더 많이 겹치게 하도록 안내가 필요하다.
- 촬영 높이 검사는 합성 사진(모두 1.45m)에서만 검증했다. 실제 촬영 높이 분포에서 기준을 다시 확인해야 한다.
- 실 용도 이름(침실·욕실 등)은 도면에 있지만 문자 인식이 없어 쓰지 않았다. 평면도 2장뿐이다.
